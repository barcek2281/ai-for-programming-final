# Решения, принятые при реализации

Здесь записано всё, что ТЗ (v0.4) не определяло или где пришлось выбрать более простой вариант.

## Версии и окружение

| # | Решение | Почему |
| --- | --- | --- |
| 1 | Корень репозитория — эта папка, без вложенной `vivamind/` | Так проще запускать; структура внутри — как в разделе 5 ТЗ |
| 2 | Spring Boot **4.1.2**, Spring AI **2.0.1**, AWS SDK 2.59.1 | Актуальная согласованная связка по Spring Initializr на 15.11.2026 |
| 3 | SeaweedFS закреплён на **4.53** | ТЗ требовало закрепить версию 4.42+. Команда `mini -dir -s3.config -bucket -admin.port` из ТЗ на этой версии работает |
| 3а | Админка SeaweedFS (порт 12646) с хоста не открывается | В версии 4.53 интерфейс без пароля слушает только loopback внутри контейнера. Открывать его флагом `-admin.allowInsecureBind` не стали: приложению нужен только S3 API на 8333 |
| 4 | `OPENROUTER_BASE_URL` — **с `/v1`** (`https://openrouter.ai/api/v1`) | Проверено: с этим адресом запрос эмбеддингов доходит до OpenRouter (без ключа ответ 401, а не 404). Вариант без `/v1` не понадобился |
| 5 | В Spring AI 2.0.1 `.options(...)` принимает **builder** (`OpenAiChatOptions.builder().model(..).temperature(..)`), без `.build()` | Так устроен API этой версии; в ТЗ пример с `.build()` |
| 6 | Настройки эмбеддингов: `encoding-format: float`, `metadata-mode: none` | `float` понимают все провайдеры; `none` — в эмбеддинг идёт только текст фрагмента, без служебных метаданных |
| 7 | Для геттеров/сеттеров сущностей подключён Lombok | Меньше шаблонного кода, сущности читаются как описание таблиц |
| 8 | Maven не требуется — в `backend/` лежит Maven Wrapper | На машине разработчика Maven не установлен |

## Авторизация

| # | Решение | Почему |
| --- | --- | --- |
| 9 | JWT выпускается и проверяется готовыми `NimbusJwtEncoder` / `NimbusJwtDecoder` из Spring Security (HS256) | Не пишем криптографию руками. Это не OIDC: стартер `oauth2-resource-server` используется только ради этих двух классов |
| 10 | Ключ подписи = SHA-256 от `JWT_SECRET` | HS256 требует ровно ≥ 32 байт; так приложение не падает при коротком секрете |
| 11 | Добавлены `GET/POST /api/v1/admin/teachers` и страница `/admin` | В ТЗ роль ADMIN «создаёт аккаунты преподавателей», но эндпоинта в разделе 10 нет |
| 12 | Добавлена переменная `SEED_DEMO_PASSWORD`; комментарий к `SEED_DEMO_USERS` вынесен на отдельную строку | В ТЗ пароль демо-аккаунтов не задан; комментарий в конце строки ломает разбор `.env` как properties-файла |

## Интервью

| # | Решение | Почему |
| --- | --- | --- |
| 19 | Обработка ответа — в три шага: транзакция (сохранить ответ) → вызов LLM без транзакции → транзакция (решение `TurnPolicy`) | Не держим соединение с БД и блокировку строки, пока отвечает модель |
| 20 | Если LLM не ответила, сохранённый ответ студента **удаляется**, клиент получает 503 и может отправить текст ещё раз | Не подменяем ИИ заготовленным вопросом — это была бы симуляция. Интервью при этом не «зависает» |
| 21 | Ответ студента, после которого 150 с нет реплики ИИ, считается сорвавшимся и заменяется новой отправкой | Восстановление после падения сервера посреди хода |
| 22 | «Не знаю» и пустой ответ по таймауту — всегда `ABSENT`, что бы ни вернула модель | Прямое требование п. 3.1; так два «Не знаю» гарантированно закрывают вопрос |
| 23 | `TurnDecision` сохраняется в `messages.turn_decision` у **ответа студента**, к которому он относится | Удобно для аудита: видно, как модель оценила конкретную реплику |
| 24 | Повторный «старт» при незаконченной сессии возвращает её же | Студент может вернуться в интервью после закрытия вкладки |
| 25 | При закрытии экзамена незаконченные сессии получают статус `ABANDONED` | В ТЗ статус есть, но не сказано, когда он ставится |
| 26 | Код доступа — 6 символов без похожих знаков (0/O, 1/I/L) | Его диктуют в аудитории; в колонку `VARCHAR(8)` помещается |
| 27 | Настройки экзамена меняются только в статусе `DRAFT` | После публикации студенты уже могли начать интервью |
| 28 | Текст студента в промптах экранируется (`<` → `&lt;`) | Чтобы нельзя было «закрыть» тег `<student_answer>` и выдать свой текст за инструкцию |

## Оценивание

| # | Решение | Почему |
| --- | --- | --- |
| 29 | В `session_questions.ai_grade` хранится `QuestionGrade` плюс служебные поля: `removedQuotes`, `needsReview`, `reviewReasons`, `failed` | Флаг «вопрос на проверку» из п. 9 ТЗ негде больше хранить — отдельной колонки в схеме нет |
| 30 | Если ИИ не смог оценить вопрос, записывается `failed = true`, сессия всё равно доходит до `AI_GRADED` с флагом проверки | Преподаватель ставит уровень вручную или жмёт «Перезапустить ИИ-оценку» |
| 31 | `final_score` записывается только при подтверждении. До этого экран проверки показывает расчётный `previewScore` | «Итог только после confirm преподавателя» (п. 12.1) |
| 32 | Тренировочные (`PRACTICE`) сессии не подтверждаются | «Оценка в журнал: нет» (п. 3.4) |
| 33 | Апелляция — одна на сессию. Если новые уровни дают балл ниже текущего, запрос отклоняется (400) | «По итогам апелляции балл нельзя понизить» |
| 34 | В отчёте студента нет ключевых идей и рубрики карточки — только уровень, цитаты, пробелы и свой диалог | Чтобы не раскрывать банк вопросов следующим студентам |
| 35 | Итог по сессии собирается под блокировкой (вопросы оцениваются параллельно) | Иначе отчёт мог бы сформироваться дважды |
| 36 | «Что перечитать»: для пробелов подбираются фрагменты темы, а из ответа модели выкидываются файлы, которых нет в материалах | Модель не должна выдумывать источники |

## Материалы и RAG

| # | Решение | Почему |
| --- | --- | --- |
| 37 | В метаданные фрагмента добавлен `chunkId` (его же id) | Позволяет доставать источники карточки через фильтр `VectorStore`, без своего SQL к `vector_store` |
| 38 | Текст страниц PDF очищается от серий пробелов перед разбиением | `PagePdfDocumentReader` сохраняет вёрстку пробелами — это раздувает фрагменты и промпты |
| 39 | `materials.pages` = число страниц **с текстом** | Пустые страницы и сканы без текстового слоя читатель пропускает |
| 40 | В `llm_calls` с назначением `EMBED` пишется одна строка на загруженный материал (без токенов) | Эмбеддинги считает Spring AI внутри `vectorStore.add()`, usage там недоступен |
| 41 | Источники карточки: оставляем только id, которые модель реально получила; если она не назвала ни одного — берём все переданные | «Проверка источников карточки» (п. 7.2) |

## Доработки после первого показа (15.11.2026)

| # | Решение | Почему |
| --- | --- | --- |
| 46 | Кроме PDF принимаются DOCX и PPTX; их читает `TikaDocumentReader` из Spring AI | Материалы курса часто лежат в Word и PowerPoint. У таких файлов нет номеров страниц, поэтому в ссылках «что перечитать» указывается только файл |
| 47 | Добавлен `POST /outcomes/{id}/cards`: преподаватель пишет вопрос сам, он сразу `APPROVED`, `ai_generated = false` | Преподаватель не должен зависеть от ИИ при составлении вопросов |
| 48 | Миграция `V2`: колонка `exams.same_questions`. Если включено, вопросы выбираются с seed = id экзамена, а не id сессии | По просьбе преподавателя: у всех студентов одинаковый набор базовых вопросов. Углубления всё равно разные — они строятся на словах студента. В форме создания экзамена галочка включена по умолчанию |
| 49 | В интерфейсе «карточки» названы «вопросами» | Слово «карточка» было непонятно без пояснений |

## Что осталось проверить вручную

- Сквозной сценарий (загрузка PDF → карточки → интервью → оценка → подтверждение → отчёт → апелляция) проверен
  на **тестовой заглушке** OpenAI-совместимого API. С реальным ключом OpenRouter нужно пройти `docs/demo.md` и
  убедиться, что выбранные модели стабильно возвращают корректный JSON.
- Финальный выбор моделей — после прогона 10 реальных ответов на казахском и русском (п. 8.2 ТЗ).
